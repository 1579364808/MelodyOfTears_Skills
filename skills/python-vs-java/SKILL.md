# Python vs Java 语法对照解释

## 何时触发

用户提及任何 Python 语法/写法/关键字/语言特性时，**必须**触发本 skill——尤其是用户表达看不懂、不理解时。

用户的身份: **有 Java 编程经验，正在学习 Python**。

## 核心原则

1. **永远用 Java 做对比** —— 不要孤立地解释 Python，而是要给出 Java 的对应写法
2. **用表格总结** —— 每次解释完，用 Markdown 表格列出 Python vs Java 的核心差异
3. **给可运行示例** —— Python 代码要简短可运行，Java 代码展示对比
4. **关联已有笔记** —— 如果内容与 `对比Java学习python/` 目录下已有文件相关，提示用户可以去查看对应文件

## 解释结构

按以下顺序组织回答：

### 1. 一句话定性
用一句话说明"Python 的 X 相当于 Java 的 Y"

### 2. 代码对比
并排展示两段代码（或先后展示），Java 代码标注为熟悉方：
```python
# Python 写法
```

```java
// Java 对应写法
```

### 3. 差异表格
| 对比项 | Python | Java |
|--------|--------|------|

### 4. 要点说明
列出 2-3 个最容易踩坑或最重要的注意事项。

### 5. 更新笔记文件（必须）
**每次解释完后，必须将本次内容写入 `对比Java学习python/` 目录下的一个 Markdown 文件。**

规则：
- 如果本次主题尚未有对应文件，**新建一个**，按序号命名（如 `03-xxx对比.md`、`04-xxx对比.md`）
- 如果本次主题与已有文件部分重叠，**更新该文件**，追加或补充相关内容
- 文件格式与已有文件保持一致：开头标题，然后 Python vs Java 代码对比，差异表格，要点说明
- 编号接续已有文件的最大序号

### 6. 关联已有笔记（可选）
如果匹配已有文件，提示用户。

## 回答风格

- 简短直接，不必铺垫
- 不必说"这是一个很好的问题"之类废话
- 重点突出差异，不要面面俱到讲 Java 基础
- 用户可能连续追问，每次回答独立完整但保持简洁
