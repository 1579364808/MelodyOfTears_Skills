# 进度与门禁规则

## 章节状态模型

- `pending`：未开始
- `ready`：已产出章纲，等待许可
- `in_progress`：已获许可，正在讲解
- `done`：本章完成并复盘

## 门禁触发条件

允许进入正文讲解的唯一条件：用户明确同意。

涉及公式时的附加条件：章节文档中的公式必须先满足 LaTeX 渲染规范。

正文输出前置条件（新增强约束）：
- 已将当前轮详细讲解内容写入对应 `chapter-0X.md`
- 已同步更新 `progress.md`，并将状态置为 `in_progress`
- 已完成一次“渲染兼容自检”并记录

有效同意示例（同义表达均可）：
- 同意开始本章
- 继续本章
- 开始讲这一章

若无明确同意：
- 仅允许调整章纲
- 仅允许补充学习节奏与产出定义
- 禁止输出正文讲解

若满足同意但前置条件不满足：
- 必须先修正文档与进度
- 禁止先在对话中讲解正文

## 异常处理

- 用户跳章：先提示影响，再请求确认是否重排章节。
- 用户要求“直接讲”：先提供章纲并执行门禁确认。
- 用户中断：保持当前状态，不自动推进下一章。
- 用户指出“未写入文档/未渲染”：立即回退到“修正文档优先”流程，修复后再继续讲解。

## 文档同步约束

- 任何章节推进都必须同步更新对应 `.md` 文档。
- 若文档更新失败，应先修复文档路径或权限，再继续教学流程。
- 若章节包含数学表达，推进前后都要检查 LaTeX 公式可渲染性。
